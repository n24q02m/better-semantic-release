## 2023-11-20 - Command Injection in GitHub Actions Output
**Vulnerability:** GitHub Actions environment variables (like `$GITHUB_OUTPUT`) populated with multiline values using a hardcoded `EOF` delimiter are vulnerable to injection attacks if the content contains the string `\nEOF\n`.
**Learning:** This codebase incorrectly implemented GitHub Actions multiline strings using a static `EOF` string. When creating variables out of user-controlled input (like commit messages appearing in `release_notes`), a malicious commit message could break out of the multiline variable and define new environment variables or outputs.
**Prevention:** Always use a randomly generated delimiter (e.g. `uuid.uuid4().hex`) to ensure there is no possibility of collisions or command injection when writing to `$GITHUB_OUTPUT`.
## 2026-07-28 - [Local File Read / SSRF via urllib Request]
**Vulnerability:** A local file read (and potentially Server-Side Request Forgery) was possible in `src/semantic_release/bsr/registry.py` inside `_http_status` by supplying a non-HTTP scheme like `file:///etc/passwd` to `urllib.request.urlopen`.
**Learning:** `urllib.request.urlopen` in Python handles multiple schemes by default (including `file://`). Security linters (Bandit B310) flag this correctly, but a `# noqa` suppression isn't enough; the code must actually validate the protocol scheme if the URL is dynamically generated or controlled by an external source.
**Prevention:** Always restrict accepted schemes to `http` and `https` via string prefixes or parsed URL schemes before calling `urlopen` or similar HTTP-fetching libraries that support additional protocols.
