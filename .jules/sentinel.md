## 2025-03-09 - Fix SSRF Bypass via Obfuscated Loopback IPv6 with Zone Identifiers
**Vulnerability:** The registry HTTP probe was vulnerable to Server-Side Request Forgery (SSRF) bypasses. When validating URLs for loopback or link-local addresses, `urllib.parse.urlparse` parses malformed IP literals (such as unbracketed IPv6 with zone identifiers, e.g., `http://127.0.0.1%en0/` or `http://fe80::1%en0/`) either incompletely or by returning `None` for the `hostname`. This allowed internal IP addresses to bypass the `_is_blocked_host` check and still be reached by `urllib.request.urlopen`.
**Learning:** `urllib.parse.urlparse` cannot be relied upon to extract the hostname reliably when IP literals are obfuscated with trailing zone identifiers or brackets. When validating against an SSRF blocklist, you must fall back to parsing `netloc` directly and strip zone IDs (`%`) before validating with `ipaddress`.
**Prevention:** Always handle the case where `urllib.parse.urlparse().hostname` is `None` or incomplete. For SSRF protections, fall back to parsing `netloc` directly and clean the host string (e.g. stripping `[]` and splitting on `%`) before attempting to convert to an IP address or comparing against blocklists.
